# Endpoints deferred to findata-ext (not declarative)

These read endpoints can't be expressed as a single parameterized SELECT and stay compiled.

- `/ratios/:symbol` (fundamentals+analysis): pivot_raw: moves `raw` jsonb into a `ratios` key, drops 7 upstream meta keys, and coerces every remaining leaf value to float-or-null — jsonb reshaping not expressible in declarative SQL.
- `/financial-growth/:symbol` (fundamentals+analysis): pivot_raw: reshapes `raw` jsonb into `growth` map, drops meta keys, per-value float coercion — not declarative.
- `/income-statement-growth/:symbol` (fundamentals+analysis): pivot_raw: reshapes `raw` jsonb into `growth` map, drops meta keys, per-value float coercion — not declarative.
- `/balance-sheet-growth/:symbol` (fundamentals+analysis): pivot_raw: reshapes `raw` jsonb into `growth` map, drops meta keys, per-value float coercion — not declarative.
- `/cash-flow-growth/:symbol` (fundamentals+analysis): pivot_raw: reshapes `raw` jsonb into `growth` map, drops meta keys, per-value float coercion — not declarative.
- `/analyst-estimates/:symbol` (estimates+investors): Long-to-wide pivot building a nested per-period `metrics` jsonb map in code (HashMap aggregation across metric rows), plus a dynamic ranked_periods CTE with conditional since/period WHERE — not expressible as a flat row/envelope query.
- `/holders/:symbol/top` (estimates+investors): Two-query orchestration: resolves `asof` from a separate max(report_period) lookup when omitted, returns a null-as_of empty envelope branch, and emits a custom envelope {symbol,as_of,count,holders} (non-standard key + as_of field).
- `/fund-ownership/:symbol` (estimates+investors): Two-query orchestration: resolves `asof` from a separate max(as_of) lookup when omitted, null-as_of empty-envelope branch, custom envelope {symbol,as_of,count,funds}.
- `/funds-disclosure/:symbol` (estimates+investors): Custom envelope shape {symbol,count,funds} with non-standard 'funds' data key (differs from the standard {symbol,count,data} envelope); byte-identity requires the bespoke key name.
- `/news/latest` (news): Dynamic WHERE built in code from optional category param via category_alias() with arbitrary passthrough fallthrough (not an enum allow-list), so SQL/params cannot be statically declared.
- `/news/search` (news): Dynamic WHERE built in code: required q tsquery (websearch_to_tsquery) plus optional category via category_alias() passthrough mapping; conditional clause construction not expressible declaratively.
- `/news/stats` (news): Returns custom-wrapped object {"categories":[...]} (not the standard {symbol,count,data} envelope nor rows/one); response shape outside the supported shape set.
- `/market-cap/:symbol/history` (corpactions+valuation+etf+earnings): Handler runs the SQL with ORDER BY date DESC then re-sorts the result set ASCENDING in code (post-query stable sort by date string). Output is ascending; declarative single-query SQL with DESC LIMIT cannot reproduce the in-code reversal of the LIMIT-bounded window byte-identically. Also has optional start/end dynamic WHERE.
- `/etf/:symbol/holdings` (corpactions+valuation+etf+earnings): Multi-query orchestration + jsonb envelope shaping: pre-query computes max(as_of) when asof param absent, returns a custom JSON object {etf_symbol, as_of, count, holdings:[...]} (not a row array or standard envelope), and short-circuits to a literal {count:0, holdings:[]} object when no as_of exists. Dynamic two-step + bespoke shape can't be declared.
- `/earnings` (corpactions+valuation+etf+earnings): Dynamic WHERE built in code from optional symbol/start/end query params with positional bind index shifting; collection-level route (no path symbol). Optional-bind dynamic WHERE construction is outside the enum-fragment model.
- `/dividends/:symbol` (corpactions+valuation+etf+earnings): Optional `since` date param produces a conditional `AND date >= since` WHERE clause built dynamically in code. If the declarative layer supports optional bound filters use the block above; otherwise this stays in findata-ext due to the dynamic WHERE.
- `/peers/:symbol` (reference+macro+events): Returns a flat JSON array of peer_symbol strings (Vec<Value::String>), not row objects — shape is incompatible with the rows/one/envelope object-array contract.
- `/symbol-changes` (reference+macro+events): Dynamic WHERE: optional symbol expands to a 3-way bound OR (symbol/old_symbol/new_symbol) plus optional since; optional value-bound filters built in code, not expressible via enum allow-list.
- `/exchange/:exchange/holidays` (reference+macro+events): Dynamic WHERE with optional value-bound from/to (holiday_date >= / <=) filters built in code alongside the required exchange equality.
- `/exchange-market-hours` (reference+macro+events): Handler computes an `is_open` boolean per row in Rust from timezone/offset parsing and current wall-clock — not expressible in SQL/TOML; also optional exchange filter.
- `/macro/treasury-rates` (reference+macro+events): Optional value-bound from/to date filters built dynamically, AND the result is re-sorted ascending in Rust after a DESC LIMIT (top-N-newest then reorder) — needs a subquery wrapper plus dynamic WHERE.
- `/macro/economic-indicators` (reference+macro+events): Dynamic WHERE: optional value-bound indicator equality and optional since date filter built in code.
- `/macro/economic-calendar` (reference+macro+events): Dynamic WHERE: optional value-bound since/until/country/impact filters built in code.
- `/ipos` (reference+macro+events): Dynamic WHERE: optional value-bound from/to (ipo_date) filters built in code.
- `/mergers-acquisitions` (reference+macro+events): Dynamic WHERE: optional value-bound since/accepting_symbol/target_symbol filters built in code.
- `/fda-calendar` (reference+macro+events): Dynamic WHERE: optional value-bound since (from_date >=) filter built in code.
- `/technical/:symbol` (transcripts+institutional+technical+marketextras+regulatory): start/end query params default to handler-computed Utc::now() and now-365d window; the time-window defaults are computed in code, and the envelope carries a dynamic top-level "indicator" field (echoed param or "all"), neither expressible via static TOML.
- `/institutional/:symbol/holders/analytics` (transcripts+institutional+technical+marketextras+regulatory): envelope adds a top-level "symbol" field (uppercased path param) alongside {count,data}; the {symbol,count,data} variant is not the plain envelope shape (which uses no symbol for these) — needs handler-side symbol echo plus year/quarter date-extract filters.
- `/sectors/pe` (transcripts+institutional+technical+marketextras+regulatory): SQL self-references max(snapshot_date) subquery on market.sector_pe_snapshot with optional exchange filter that toggles a parameterized vs unparameterized query in code; the WHERE/ORDER BY are built dynamically (exchange present or absent) — keep compiled.
- `/sectors/performance` (transcripts+institutional+technical+marketextras+regulatory): same dynamic max(snapshot_date)+optional-exchange query construction as /sectors/pe (market.sector_performance_snapshot).
- `/industries/pe` (transcripts+institutional+technical+marketextras+regulatory): same dynamic max(snapshot_date)+optional-exchange query construction (market.industry_pe_snapshot).
- `/industries/performance` (transcripts+institutional+technical+marketextras+regulatory): same dynamic max(snapshot_date)+optional-exchange query construction (market.industry_performance_snapshot).
- `/index/:index_symbol/constituents` (transcripts+institutional+technical+marketextras+regulatory): as_of query param defaults to handler-computed today(); envelope carries dynamic top-level index_symbol + as_of (echoed/computed) fields beyond {count,data} — date default + extra envelope keys are computed in code.
- `/prediction-markets/markets/search` (predictionmarkets+kols): search_markets builds a dynamic UNION ALL in code, branching the SELECT/WHERE on venue (poly/kalshi) and status (open/closed/all); not a fixed SQL.
- `/prediction-markets/markets/kalshi/:ticker` (predictionmarkets+kols): Handler upper-cases the ticker bind value (ticker.to_uppercase()); no declarative param type upper-cases a non-symbol path param.
- `/prediction-markets/trades/polymarket/:condition_id` (predictionmarkets+kols): time_bounded() constructs the WHERE clause dynamically based on optional from/to query params (conditional bind positions).
- `/prediction-markets/trades/kalshi/:ticker` (predictionmarkets+kols): Dynamic WHERE for optional from/to (time_bounded) plus ticker.to_uppercase() bind transform.
- `/prediction-markets/orderbook/polymarket/:asset_id` (predictionmarkets+kols): time_bounded() builds WHERE dynamically for optional from/to query params.
- `/prediction-markets/orderbook/kalshi/:ticker` (predictionmarkets+kols): Dynamic WHERE for optional from/to plus ticker.to_uppercase() bind transform.
- `/prediction-markets/open-interest/:venue/:market_id` (predictionmarkets+kols): Fetches newest N (ORDER BY bucket_ts DESC LIMIT) then out.reverse() to oldest-first in code; not reproducible with a single ORDER BY + LIMIT.
- `/prediction-markets/wallet/:address` (predictionmarkets+kols): wallet_profile lower-cases the address bind value (wallet.to_lowercase()); no declarative param type lowercases the value.
- `/prediction-markets/wallet/:address/pnl` (predictionmarkets+kols): Lower-cases wallet bind AND does out.reverse() post-processing (newest-N, oldest-first).
- `/prediction-markets/wallet/:address/positions` (predictionmarkets+kols): wallet_positions lower-cases the wallet bind value.
- `/prediction-markets/wallet/:address/activity` (predictionmarkets+kols): wallet_activity lower-cases the wallet bind value.
- `/prediction-markets/leaderboard` (predictionmarkets+kols): Handler canonicalizes window via window_alias() and validates venue in code; query uses an i32-cast limit bound twice (rank <= $2 LIMIT $2) — orchestration not expressible declaratively.
- `/prediction-markets/events` (predictionmarkets+kols): polymarket_events builds the WHERE clause dynamically (optional q search + status branch); not fixed SQL.
- `/kols/tweets` (predictionmarkets+kols): recent_tweets reads from Redis (lrange per-handle), merges/sorts in memory, then project_recall reshapes; no SQL.
- `/kols/tweets/search` (predictionmarkets+kols): kols.search builds dynamic WHERE for optional until, default_since fallback, plus project_archive + attach_proxy_urls post-processing/shaping.
- `/kols/tweets/by-symbol/:symbol` (predictionmarkets+kols): tweets_for_symbol reads live tweets from Redis (lrange kol_tweets:by_symbol) + project_recall reshaping; no SQL.
- `/kols/tweets/by-symbol/:symbol/history` (predictionmarkets+kols): history_by_symbol builds dynamic WHERE (optional until/handle), default_since fallback, array-cast cashtag bind, plus project_archive + attach_proxy_urls shaping.
- `/kols/archive/stats` (predictionmarkets+kols): archive_stats uses a count(distinct kol_username) subquery and post-query inserts last_ingest=null; count-distinct is barred on TimescaleDB and the response is shaped in code.
- `/kols/:handle/tweets` (predictionmarkets+kols): tweets_for_handle reads live tweets from Redis (lrange kol_tweets:by_handle) + project_recall reshaping; no SQL.
- `/kols/:handle/tweets/history` (predictionmarkets+kols): history_by_handle builds dynamic WHERE (optional until/cashtag), default_since fallback, handle/cashtag bind transforms, plus project_archive + attach_proxy_urls shaping.
